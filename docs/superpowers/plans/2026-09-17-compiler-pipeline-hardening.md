# Compiler pipeline hardening — task list

Source: an external static review of the compiler path (evaluate → link →
normalize/simplify → assemble → generate), every finding verified against
the tree on 2026-09-17. Ordered by value per unit of risk. Every task is a
byte-identical refactor under the standing gate (regenerate all three
grammars, zero diff in `packages/<lang>/src`) unless the task says otherwise.

Gates for every task: `pnpm -r --no-bail run type-check` (only the
pre-existing `packages/types` vocabulary errors allowed), the codegen suite
with no new failures, and the regen diff check. Native validation is run
where the environment allows it.

## Phase 2 — one compilation, one gate

### Task 6: `compileGrammar()` → `Compilation` → `assertCompilation()` → emit

The spine; Tasks 7–9 land inside it.

- Today `runCodegen` runs `runGrammarDiagnosticsPreflight` (`run-codegen.ts:197`
  → `grammar-diagnostics.ts:172-232`: link → normalizeGrammar → assemble)
  and then `generate()` (`:204`) repeats evaluate → link → normalize →
  assemble. `assertEmittable` (`emit-gate.ts:4-8`) takes `_nodeMap` and never
  reads it; the preflight's parse-kind, derive-shape, assembly, slot,
  content-alias and kind-id checks never reach a library caller of `generate()`.
- Introduce `compileGrammar(cfg): Compilation` holding `{ raw, linked,
  normalized, nodeMap, diagnostics }`, extending `BaseCtx` rather than adding
  a second context type. `grammar-diagnostics` becomes a set of checks over a
  `Compilation`; `assertCompilation` replaces `assertEmittable` and runs them.
  `generate()` and `runCodegen` both consume one `Compilation`; the preflight
  is a call to the same checks, not a second compile.
- After `compileGrammar` returns, no compiler graph mutation is permitted:
  hydration (Task 8) happens inside it, and the `NodeMap` is sealed
  (`Object.freeze` on the map and node arrays, or a sealed accessor) before
  emitters see it.
- Test: `generate()` alone rejects a grammar that the preflight rejects today
  (pick one existing diagnostics fixture per class).
- Done: `evaluate` runs once per CLI generation (assert via a call counter in
  a test); `emit-gate.ts` is gone.

### Task 7: Session-owned state, reentrant `evaluate()`

- `evaluate.ts:1100-1135`: `saveAndInjectDslGlobals` writes the DSL onto
  `globalThis`, awaits `importAndExtractGrammar`, restores in `finally` —
  two concurrent calls interleave save/restore. Removing the injection is a
  grammar-authoring contract change (`.sittir/grammar.js` is written against
  tree-sitter's global DSL and executes twice by design), so it is out of
  scope here: serialize `evaluate()` behind a module-level async mutex.
- `generate.ts:79-85` registers `addUnnamedChoiceListener`; removal at `:197`
  is on the success path only — move to `finally`. Registry is module state
  (`collect-slots.ts:49-50, :173`).
- Module accumulators — `simplify.ts:196-197` (`_slotGroupingDiagnostics`),
  `node-map.ts:40-41, 71-72, 99-100` (parse-kind collision, derive-shape,
  assemble warnings), drained by `drainSlotGroupingDiagnostics` /
  `resetSlotGroupingDiagnostics` (`normalize.ts:250`) — move onto the
  `Compilation`'s `DiagnosticSink`; delete the drain/reset functions.
- Test: two `compileGrammar` calls for different grammars run concurrently
  produce the same node maps as when run sequentially.
- Done: no `let`/mutable module-level collector remains under
  `packages/codegen/src/compiler`; `grep -n globalThis` shows only the
  mutex-guarded injection.

### Task 8: Unresolved internal refs enter the sink; hydrate before the gate

- `generate.ts:120` `assertEmittable` precedes `:137` `hydrateSlotRefs`.
  `assemble.ts:640-663` `hydrateValues` writes to stderr (unless
  `SITTIR_QUIET`) on an unresolved non-external target and leaves the
  `UnresolvedRef` in place.
- Classify at the ref: `external` / `parser-only` (legitimate, emitters
  understand them) versus `dangling-internal`. The latter becomes a blocking
  `DiagnosticSink` entry with the owning node, slot and target name. Hydration
  moves inside `compileGrammar` (Task 6) so `assertCompilation` sees it.
- Baseline first: run hydration on all three grammars and record the
  current count of each class; the dangling-internal count must be zero or
  every instance explained before the diagnostic is made blocking.
- Done: no `process.stderr.write` in `assemble.ts`; a test grammar with a
  dangling internal ref fails `assertCompilation` by name.

### Task 9: Serialize `node-model.json5` after hydration

- `generate.ts:135` `emitNodeModel` precedes `:137` `hydrateSlotRefs`; the

## Phase 3 — loud caps, then measure

### Task 10: Every iteration cap is a blocking diagnostic

- Five caps, three behaviors: `simplify.ts:315-332` `MAX_ITERS = 16`
  (`console.warn`, returns last state); `normalize.ts:254-258` 8 passes of
  `inlineHiddenSeqRefs` (silent); `normalize.ts:493-513`
  `iterateInliningToFixedPoint` 4 passes (silent); `flatten.ts:224-237` 16
  (silent); `link.ts:782-797` 64 (warn diagnostic `inline-fixpoint-unreached`,
  `canProceed: true`).
- Unify: one helper `runToFixpoint(name, step, cap)` that raises a blocking
  diagnostic naming the pass when the cap is hit; no warn-and-continue path.
- Then measure: log iterations-to-convergence per pass for all three
  grammars. Record the numbers in the plan's completion note. If every pass
  converges well under its cap, the worklist rewrite is deferred; if any is
  within a factor of two, that pass gets a monotone bound (count of
  eligible refs/wrappers) instead of a number.
- Done: no `console.warn` in the compiler passes; a fixture that cycles fails
  compilation by pass name.

# Strict rebuild from source — the factory emitter and the gaps it measures

> **Status:** Design (2026-09-07). Follows the skip-list retirement; depends on
> the value-storage taxonomy (a value that resolves to a kind is stored as
> its kind id).

## Problem

The dogfood examples (`examples/17-dogfood-rust-strict.ts` and its two
siblings) are the only measure of whether the strict construction surface
can build a real file, and they measure nothing: each rebuilds its target's
skeleton and stops, their headers claim the whole file rebuilds, the
verification assertions that compare against the target are `it.fails`, and
the files are excluded from `type-check:examples`, so a call that no longer
type-checks is not even reported. The factory-render-parse validator, by
contrast, proves at runtime that every corpus node rebuilds through its
factory (`nodeToConfig` → factory → render → parse, rust 1517/1517), but it
leaves no source behind that a reader could compare with the surface they
would write.

Making one token tree in the rust example strict exposed the shape of the
gap: the tokens of `#[derive(Debug, Clone)]` are `token_tree_punctuation`
nodes, and the strict surface has no way to spell one. The kind is an enum
of literal tokens (`,`, `+`, `::`, …); the storage taxonomy already says a
slot holding such a value stores the literal's kind id — `function_modifiers`
stores `TSKindId.Async` — but the classifier only sees an enum leaf that is a
slot's direct arm. `_delim_tokens` reaches `token_tree_punctuation` through
the `_non_special_token` supertype, so the slot stores a node, the node needs
a factory, and `ir` exposes none.

## Decision

### Enum and keyword arms are found through supertypes

`classifyFieldStorageInfo` resolves a slot arm that is a transparent
supertype by walking its subtypes, recursively: an enum or keyword subtype
contributes its kind ids and texts exactly as a direct enum or keyword arm
does; any other subtype is a node arm. `kindEnumTextIdPairs` consumes the
same walk instead of repeating it. The slot is then `mixedEnum` (or
`kindEnum` when nothing else remains), typed `TSKindId.Comma | TSKindId.Plus
| … | Identifier | …`, read through `projectMixedEnumStorage`, rendered as
the literal's text, and the factory takes the kind id. The enum leaf's own
factory and `Terminal` type stay for the leaf as a kind (it is still a
parser node), but no slot needs them.

The caller's spelling is the ruling: a token in a token tree is
`TSKindId.Comma`, not a call. No leaf factory for an enum-of-literals kind
is added to `ir`.

### One emitter prints what the validator already builds

`sittir tool emit-factory-source --grammar <g> --file <path> [--export
<name>] [--out <file>]` parses the file, reads it through the grammar's
`readTreeNode`, and prints the strict factory source that rebuilds it. It
does not re-derive the node-to-call mapping: it runs
`buildFactoryNodeFromReference` with a factory map whose every entry, instead
of building, returns a printed-call marker carrying the kind's numeric
`$type`; the marker is what `resolveChild` places into the parent's config,
and the printer serialises the finished config. Each factory shape prints
the call the validator would make:

| shape | printed |
| --- | --- |
| `config` | `ir.<key>.strict({ <camelSlot>: <value>, … })` |
| `direct` / `forwarded` | `ir.<key>.strict(<value>)` |
| `elements` | `ir.<key>.strict({ delimiter: Delimiter.<Arm> }?, <element>, …)` |
| `spread` | `ir.<key>.strict(<child>, …)` |
| `text` | `ir.<key>(<text>)` |

A value that is a kind id in the catalog prints as `TSKindId.<Member>`; a
string prints as a string literal; `undefined` slots are omitted. A hidden
kind that is a polymorph form prints through its parent's bundle,
`ir.<parentKey>.<form>.strict(…)`, the form named as the overlay names it
(`camelCase(variant)`); a hoisted kind prints where its parent's
config-merge form places it. A node's attached trivia prints as
`.$trivia({ leading: [<text>, …], trailing: [<text>, …] })` with the
comments' verbatim text, since `$trivia` accepts a string as verbatim text
and a comment's exact spelling is the point.

The output is a module: `import { ir, TSKindId, Delimiter } from
'@sittir/<g>';` and one exported function returning the root. It is
formatted by the repo's formatter and marked `@generated`.

### The generated rebuilds are the dogfood gate

For each grammar the emitter's output for the existing dogfood target is
checked in as `examples/<n>-dogfood-<g>.generated.ts` beside the
hand-written pair, regenerated by `pnpm run gen:examples`, and never
hand-edited. `examples/tsconfig.json` includes every dogfood file, so a
call the surface cannot type is a type-check failure by name. The package
verify tests import the generated module and assert, as ordinary `it`
cases, that it renders, re-parses to the target's tree, and that
regenerating it reproduces the checked-in file byte for byte. The
hand-written strict examples keep narrating the calling conventions; their
headers state what they build.

## Blast radius

- Every slot that reaches an enum or keyword kind through a supertype
  changes storage class. The census is part of landing it: the generated
  types diff names every kind, and the render, counts and byte gate must
  hold — a kind id renders as the literal's text the same way its node
  did.
- The first generated rebuilds will not type-check. Each error is a
  surface gap with a kind and a slot attached; those are the work list
  this design exists to produce, and are filed in
  `docs/factory-surface-issues.md`, not patched in the generated file.
- `nodeToConfig`'s known holes (the "polymorph: no variant matched"
  warnings the validator suppresses) print as calls that do not type-check
  or as missing children; they become visible for the first time.

## Verification

- Storage: unit test with a supertype over an enum, a keyword and a
  pattern yields `mixedEnum` with the enum's and keyword's kind ids; regen
  all three grammars; byte gate and every count identical; the types diff
  lists the reclassified slots.
- Emitter: unit tests print each factory shape from a synthetic read node;
  a real-grammar test emits `splice.rs`, writes it to a temp module,
  imports it, and asserts the render re-parses to the same tree as the
  file; the generated examples are byte-identical to a fresh emit.
- Examples: `type-check:examples` covers 16–19; the `it.fails` verify cases
  become `it` on the generated modules.

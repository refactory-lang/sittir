# Top-layer fixpoint: does enrich change a completed layer?

**Question.** Completion checks, at every layer, that enrich run once more over the layer, with the
sidecars of the enrichment the layer was built on, changes no rule. Does that hold today for each
grammar's top layer, the one `.sittir/grammar.js` exports? If it does not, which rules move, and
why? Measured on `feat/authoring-dsl-stage-0` at 88a0fa67f (`feat/authoring-dsl` 590bbe204 plus
the output gate).

**Answer.**
- rust and typescript: the top layer is a fixpoint.
- python: enrich throws on the top layer, in the split of overloaded displays:
  `enrich: newline displays an inline nonterminal; give it a rule of its own`.
  - The top layer holds `alias(alias($._newline, newline), newline)`. wire's visible-externals
    rewrite (`rewriteVisibleExternalRefsRt`) descends into an alias's content, so over its own
    output it wraps the symbol again. Each layer's wire applies it to every rule, including the base
    rules it passes through, so the bindings layer wraps layer 1's aliases a second time.
  - `grammar.json` carries the nesting. python has 10 sites: `_simple_statements`, `decorator`,
    `match_block_empty`, `suite_empty`, and six in `_layout`. rust and typescript have 8 each, all
    in `_layout`. scm and regex, which have no bindings layer, have none. No grammar's sittir layer
    has any.
  - It arrived with 64d63fc03, which hands the bindings layer to the parser: the count is 0 at
    64d63fc03~1 and on master, and 10/8/8 from 64d63fc03 on, 946114382 included.
- Un-nesting moves no parser output. With every nested alias collapsed and the parser generated by
  the pinned CLI (0.26.9, `--abi 15`, the grammar's own `tree-sitter.json`), `parser.c` and
  `node-types.json` are byte-identical to the nested grammar's, in all three grammars. Generating
  from the nested grammar reproduces the committed `parser.c` and `node-types.json` byte for byte,
  so the comparison is like for like.
- evaluate.ts holds a second copy of the rewrite for sittir's pipeline: `applyVisibleExternalsRewrite`
  over `rewriteVisibleExternalRefs`. Its glossary entry says the two produce structurally identical
  output, but this copy does not descend into precedence, token or alias rules.
  - Today it changes nothing: with it disabled, all ten evaluated-grammar snapshots still match.
  - The check is not vacuous: the function runs 39 times, and a marker rule planted in it shows up
    in all ten snapshots.

   `SITTIR_PROBE_TOP_FIXPOINT=1 pnpm exec tsx docs/superpowers/probes/2026-10-15-authoring-dsl/top-fixpoint.ts`,
   then `git apply -R` the same patch.

3. Parser neutrality, per grammar:
   - copy `packages/<grammar>/.sittir/src/grammar.json` and `packages/<grammar>/.sittir/tree-sitter.json`
     into two empty directories;
   - in one of them, replace the copy with
     `python3 docs/superpowers/probes/2026-10-15-authoring-dsl/collapse-nested-aliases.py <copy> <copy>`;
   - in each directory, run `tree-sitter generate --abi 15 -o src grammar.json`;
   - compare the two `src/parser.c` files, and the two `src/node-types.json` files.
